# Развёртывание прокси распознавания на VPS

Прокси нужен потому, что `api.groq.com` недоступен из России напрямую
(403, гео-блок). Сервер стоит в Европе и ходит в Groq сам.

Развёрнуто на `root@your.server`, домен `your.domain`, порт `9443`.

## Главное правило: только добавлять

**На сервере уже работает VLESS-VPN. Его нельзя трогать.** Поэтому:

- новый сервис на **отдельном порту** (9443), не 443 и не 2222;
- своя папка `/opt/stt-proxy`, свой пользователь, свой юнит systemd;
- никаких правок в существующей конфигурации — ни VPN, ни Docker;
- **никаких установок**: прокси на Python, только стандартная библиотека.
  Node на сервере нет, и ставить его не нужно.

Права `/etc/letsencrypt` **не меняются** — сертификат копируется к себе в
`/etc/stt-proxy`. Иначе мы бы ослабили защиту приватного ключа для чужих
сервисов, а `certbot` при продлении мог бы вернуть права назад и сломать нас.

## Что уже известно про сервер

| Что | Значение |
|---|---|
| IP | your.server |
| Домен | `your.domain` → your.server |
| Занятые порты | 22, 443 (`rw-core`, VPN), 2222 (`rw-node`), 8443 (`uvicorn`) |
| Свободный порт | **9443** |
| Python | 3.14.4, stdlib полный |
| Сертификат | `/etc/letsencrypt/live/your.domain/` (действует 58 дней) |
| Диск | 92% занято — поэтому ничего не устанавливаем |

## Развёртывание одной командой

С локальной машины:

```bash
bash deploy/push.sh your.domain 9443
```

Скрипт скопирует файлы, проверит домен и порт, и спросит ключ Groq
**на сервере** — он не попадёт ни в командную строку, ни в историю, ни в `ps`.

В конце он напечатает готовые строки для `include/config.h`.

## Что делает установка

1. Проверяет, что домен указывает на этот сервер, а порт свободен.
2. Проверяет, что `python3` и нужные модули stdlib на месте.
3. Спрашивает `GROQ_API_KEY` (без эха), генерирует `AUTH_TOKEN`.
4. Создаёт системного пользователя `sttproxy` без прав входа.
5. Кладёт прокси в `/opt/stt-proxy`, копирует сертификат в `/etc/stt-proxy`.
6. Ставит хук `certbot`, чтобы после продления сертификат обновлялся сам.
7. Заводит `/etc/stt-proxy.env` с правами 600.
8. Запускает юнит и проверяет ответы локально.

## Проверка вручную

С локальной машины, после установки:

```bash
tail -c +45 test.wav > test.lpcm
```

```bash
curl -sk -X POST https://your.domain:9443/stt -H "X-Auth: <токен>" --data-binary @test.lpcm -w '\nHTTP %{http_code}\n'
```

Должно вернуться `{"text": "..."}`.

## Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `401 unauthorized` | не тот `X-Auth` | сверить токен в `config.h` и в env-файле |
| `502 groq unreachable` | сервер не может в Groq | `curl -I https://api.groq.com` на сервере |
| `groq 401` в ответе | ключ Groq неверен | перевыпустить на console.groq.com |
| `groq 429` | лимит бесплатного тарифа | подождать |
| `413 audio too large` | больше 1 МБ | уменьшить `kMaxRecordMs` |
| `404 not found` | не тот путь | должен быть `/stt` |
| соединение не устанавливается | порт закрыт | открыть 9443 в файрволе |

Файрвол — **только для нового порта**, существующие правила не трогать:

```bash
ufw allow 9443/tcp
```

## Логи и откат

```bash
journalctl -u stt-proxy -f
```

Остановить и убрать только новый сервис:

```bash
systemctl disable --now stt-proxy
rm /etc/systemd/system/stt-proxy.service
systemctl daemon-reload
```

VPN и всё остальное продолжат работать как прежде.
