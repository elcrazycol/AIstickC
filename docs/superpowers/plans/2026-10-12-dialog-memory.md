# Память диалога — план реализации

**Goal:** модель помнит предыдущие реплики, а не отвечает на каждый вопрос с
нуля.

**Architecture:** История — последние пары «вопрос-ответ» в куче, сессионная
(до выключения, во флеш не пишем). Уходит в запрос как массив `messages`
(system + история + текущий вопрос). Обрезка по числу обменов и по бюджету
символов держит запрос компактным.

---

## Контекст

Проект `/Users/lesha/codes/aistick`, милестоуны 1–2 и UI сделаны и проверены.
Сейчас `llmreq::build` собирает `messages` из system + одного вопроса.

Решение по объёму: **5 обменов**, память **сессионная** (не переживает
выключение) — выбрано пользователем.

## Task 1: чистый модуль истории

`src/pure/chat_history.h`: `Msg { fromUser, text }`, класс `History`.

- `addUser`/`addAssistant`/`clear`/`messages`/`turnCount`/`totalChars`;
- `trim(maxChars)`: не больше `maxTurns` обменов и `maxChars` символов,
  старые обмены удаляются первыми, последний сохраняется всегда;
- после обрезки первая реплика — всегда пользователь (чередование цело).

Тесты `test/test_chat_history.cpp`: порядок, обрезка по обменам, обрезка по
символам, сохранение последнего обмена, целостность чередования, `clear`,
`nullptr`, нулевой лимит обменов.

## Task 2: сборка чата

`src/pure/llm_request.h`: `Msg { role, text }` и
`buildChat(model, msgs, maxTokens)`; прежний `build(system, user)` стал
обёрткой. Экранирование — то же, на каждую реплику.

Тесты в `test/test_llm_request.cpp`: форма массива из 4 реплик, роль,
экранирование в ответе модели, round-trip кириллицы.

## Task 3: прошивка

- `settings.h`: `kChatMaxTurns = 5`, `kChatMaxChars = 1600`.
- `llm::ask(history, question)` собирает `system + history + user`.
- `main.cpp`: после успешного ответа — `addUser`/`addAssistant`/`trim`;
  удержание BtnB очищает экран и память; заглавный экран показывает
  `В памяти: N`.

## Task 4: проверка на устройстве

Первый вопрос → уточняющий без контекста («А почему именно столько?») →
второй уточняющий. В Serial — `в памяти N обменов`. Удержание BtnB
обнуляет память.

## Согласованность

`chat::Msg` — Task 1 и 3. `llmreq::buildChat` — Task 2 и 3.
`llm::ask(history, ...)` — Task 3.

## Известный компромисс

Память не переживает перезагрузку (осознанно). Обрезка меняет префикс
запроса, поэтому prompt-кэш OpenCode частично теряется при выпадении
старого обмена — на 5 обменах это несущественно.
