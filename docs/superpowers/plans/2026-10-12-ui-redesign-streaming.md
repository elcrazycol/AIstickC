# Редизайн UI + стриминг ответа — план реализации

**Goal:** живой интерфейс: отсчёт и волны при записи, радужная полоска
прогресса, ответ появляется по мере генерации. Лимит записи 15 с.

**Architecture:** LLM-запрос идёт со `stream:true` (SSE), куски текста
отдаются наружу через колбэк и рисуются сразу. Прогресс: отправка аудио —
по реально отправленным байтам, ожидание распознавания — анимация по
времени, ответ — по принятым символам. Всё рисование вынесено в `ui.cpp`.

## Task 1: лимиты

`settings.h`: `kMaxRecordMs` 8000 → 15000 (буфер 480 КБ в PSRAM),
`kHttpReadMs` 40000 → 60000 (на слабом Wi-Fi отправка 15 с может затянуться).

## Task 2: чистый разбор SSE

`src/pure/sse.h`: инкрементальный парсер строк `data:`; копит байты,
пропускает `event:`/`id:`/комментарии/размеры chunked, отдаёт только
целые строки. Тесты `test/test_sse.cpp` — в т.ч. разрыв строки между
кусками и сохранение JSON дословно.

`llmreq::buildChat` получил флаг `stream` (`,"stream":true`).

## Task 3: стриминговый LLM

**Важное открытие о платформе.** Все модели OpenCode Go по умолчанию
«размышляют»: текст идёт в `delta.reasoning_content`, а `delta.content`
приходит пустым или в самом конце (поток рассуждений пробивал лимит в 20 КБ,
и хвост с ответом обрезался — отсюда «модель вернула пустой ответ»).
Стримить было нечего: живой текст не появлялся.

Проверено запросами: размышления отключаются параметром
`"reasoning_effort":"none"` (второй рабочий вариант —
`"thinking":{"type":"disabled"}`; `enable_thinking`, `chat_template_kwargs`,
`reasoning.enabled` не действуют). С ним — 0 reasoning-дельт, чистый ответ
208 символов и **2.2 с вместо 4.3 с**.

`llm::ask(history, question, Stream)`:
- тело со `stream:true` и `reasoning_effort:"none"`,
  `Accept: text/event-stream`;
- читает поток, декодирует chunked целиком и разбирает новый хвост;
- на каждый `delta.content` зовёт `onDelta`; `delta.reasoning_content`
  учитывается только как «активность» (страховка, если параметр проигнорят);
- `[DONE]` завершает; если `content` пуст — фолбэк на разбор обычного JSON;
- таймаут простоя 6 с.

## Task 4: колбэки прогресса в сети и STT

`net::writeAll(..., WriteProgress)` — прогресс по байтам;
`net::readAll(..., TickFn)` — тик во время ожидания.
`stt::Hooks { onUpload, onTick }` прокидывает их в STT.

## Task 5: модуль отрисовки

`src/ui.cpp/.h`: `idle`, `recording` (крупный отсчёт + радужные волны),
`progress` (радужная полоска + проценты), `text` + `bottomBar` +
`pageIndicator`. Цвет — HSV→RGB565.

`main.cpp` — диспетчер состояний
`Idle → Recording → Sending → Recognizing → Streaming → Showing`.
Волны: пиковая амплитуда каждого куска захвата в кольцевой буфер.

## Task 6: проверка на устройстве

Запись до автостопа на 15 с (волны + отсчёт), затем прогресс и живой текст
ответа.

## Известный компромисс

Проценты во время ответа оценочные: точный объём заранее неизвестен,
поэтому полоска идёт по принятым символам к мягкой цели
(`kStreamTargetChars`) и доходит до 100% по завершении. Реальный сигнал —
сам появляющийся текст. Отправка аудио измеряется точно.

Размышления отключены принудительно (`reasoning_effort:none`): для
карманного ассистента они бесполезны (пользователь их не видит), вдвое
замедляют ответ и тратят бюджет токенов.
