# Карманный голосовой ассистент на M5StickC PLUS2 — дизайн

Дата: 2026-10-11

## 1. Что делаем

Прошивка для M5StickC PLUS2: зажал кнопку → записал голос → распознал речь →
получил ответ от LLM → прочитал на экране. Один вопрос — один ответ, без памяти
диалога. Сценарий ровно как в исходном ТЗ, с поправками на реальное железо
(раздел 2).

## 2. Железо: расхождения с ТЗ

ТЗ описывает ESP32-S3 и I2S-микрофон SPM1429. Фактически железо другое, и это
влияет на код.

| Параметр | В ТЗ | Фактически |
|---|---|---|
| Чип | ESP32-S3 | ESP32-PICO-V3-02 (классический ESP32, 2 ядра 240 МГц) |
| Память | — | 8 МБ flash, 2 МБ PSRAM |
| Микрофон | SPM1429, I2S | SPM1423, **PDM** |
| Пины микрофона | DATA=G34, CLK=G0 | совпадают (G34 — данные, G0 — PDM-клок) |
| Экран | 135×240 ST7789v2 | совпадает |
| Кнопки | BtnA | BtnA=G37, BtnB=G39 (боковая), BtnC=G35 (верхняя) |
| Звук | — | пьезо-бузер на PWM, GPIO2 |

Следствия:

1. Сборка под `esp32dev`, тулчейн `xtensa-esp32` (не xtensa-esp32s3).
2. **DMA на классическом ESP32 не работает с PSRAM.** Захват идёт в DRAM-буфер
   кусками по 8 КБ, оттуда `memcpy` в PSRAM. Без этого получается белый шум.
3. **PSRAM включается вручную.** Ядро `arduino-esp32` (`esp32-hal-psram.h`)
   намеренно выкидывает `CONFIG_SPIRAM` и не вызывает `psramInit()`, если при
   сборке не определён `BOARD_HAS_PSRAM`. Флаг добавляется в `build_flags`.
   Так же сделано в вендорных board-файлах платформы (`tinypico.json` и др.).
4. Бузер — PWM, не I2S. Микрофон и динамик **не конфликтуют** за периферию,
   поэтому `M5.Speaker.end()` перед записью не нужен.
5. M5Unified уже содержит корректный профиль платы: `pin_data_in=GPIO34`,
   `pin_ws=GPIO0`, `pin_bck` не задан. Её `_setup_i2s()` включает PDM-режим
   именно когда `pin_bck < 0`. То есть PDM включается сам, вручную ничего
   настраивать не надо.

## 3. Стек и окружение

- PlatformIO, framework Arduino, платформа `espressif32` 6.13.0.
- Библиотеки: `m5stack/M5Unified`, `bblanchon/ArduinoJson`.
- Два окружения в `platformio.ini`: `esp32dev` — целевая прошивка,
  `native` — тесты чистой логики на Mac.
- Тесты чистой логики **не используют Unity**. Unity в PlatformIO скачивается
  из реестра при первом запуске `pio test`, а сети до реестра нет. Вместо него
  в `test/pure_test.h` лежит крошечная самодельная обвязка (`CHECK`, `CHECK_EQ`),
  а `tools/run_tests.sh` компилирует каждый тест обычным `clang++` и запускает.
  Это работает полностью офлайн и не требует PlatformIO вообще — то есть тесты
  можно прогонять прямо в песочнице, без железа и без сборки прошивки. Для
  модулей из `src/pure/` этого достаточно; интеграционные тесты идут на
  устройстве.

**Состояние окружения на момент написания:** PlatformIO Core на машине не
установлен (в `~/.platformio/penv` только pip и setuptools, бинарника `pio`
нет). Платформа `espressif32`, фреймворк и тулчейн скачаны. Также песочница
запрещает запись в `~/.platformio` и доступ к PyPI. Поэтому установка Core,
сборка и прошивка выполняются пользователем из своего терминала (раздел 11).
Сгенерированные артефакты (шрифт) коммитятся, чтобы для сборки Python не
требовался.

## 5. Состояния и кнопки

Состояния: `IDLE → RECORDING → STT → LLM → DISPLAY → IDLE`.

В ТЗ BtnB описан одновременно как «очистить экран» и как «следующая страница».
Разрешается так:

| Состояние | BtnA (зажать) | BtnB (тап) | BtnB (долгое) |
|---|---|---|---|
| IDLE | → RECORDING | — | — |
| RECORDING | (отпустил) → STT | отмена → IDLE | — |
| STT / LLM | игнор | игнор | — |
| DISPLAY | → RECORDING (новый вопрос) | есть страницы → следующая; последняя → очистка → IDLE | очистка → IDLE |

Детали:

- Запись автоматически останавливается на 8 секундах.
- Нажатия короче 300 мс отбрасываются как случайные.
- «Долгое» нажатие BtnB — от 800 мс.
- В DISPLAY показывается индикатор `страница/всего`, чтобы было видно, когда
  страница последняя.

## 6. Аудио

- 16 кГц, 16 бит, моно, PDM через `M5.Mic`.
- Буфер под аудио аллоцируется в PSRAM один раз на старте, не при каждой
  записи: 8 с × 32 КБ/с = 256 КБ.
- WAV-заголовок (44 байта) пишется в начало буфера, аудио — с 44-го байта.
- Захват: куски по 8 КБ в DRAM → `memcpy` в PSRAM (см. раздел 2, п. 2).
- `M5.Mic.record(buf, len, rate)` принимает **длину в сэмплах**, не в байтах.
  Передавать `int16_t*`, иначе перегрузка для `uint8_t*` даст вдвое короче.
- **Прогрев обязателен.** ПDM-микрофон при старте даёт DC-ступеньку: первые
  ~100 мс почти без переходов через ноль. Захватить и выбросить первые 200 мс,
  иначе в начало записи попадает щелчок, который портит распознавание.
- Перед записью — два коротких пика бузером, чтобы пользователь знал, когда
  говорить. Без этого он молчит в запись и получается шумовой пол.
- Микрофон инициализируется на старте: первый вызов `M5.Mic.begin()` поднимает
  I2S-периферию один раз, дальше `record()` только ставит задачи в очередь.

## 7. Сеть

### STT → Groq

`POST https://api.groq.com/openai/v1/audio/transcriptions`,
`Authorization: Bearer <GROQ_API_KEY>`, `multipart/form-data`:

- `file` — WAV из PSRAM, `model=whisper-large-v3-turbo`,
  `response_format=json`, `language=ru`.
- Ответ: `{"text": "..."}`.

Тело запроса **отправляется потоково**, а не собирается целиком в памяти:
сначала заголовки и границы частей, затем аудио кусками по 4 КБ прямо из
PSRAM, затем закрывающая граница. `Content-Length` считается заранее. Наивная
сборка тела потребовала бы второй буфер на 256 КБ.

### LLM → OpenCode Go

`POST https://opencode.ai/zen/go/v1/chat/completions`,
`Authorization: Bearer <OPENCODE_API_KEY>`, JSON:

```json
{
  "model": "deepseek-v4.1-flash",
  "messages": [
    {"role": "system", "content": "Ты карманный ассистент. Отвечай кратко, максимум 2-3 коротких предложения на языке пользователя."},
    {"role": "user", "content": "<текст из Whisper>"}
  ],
  "max_tokens": 150
}
```

Ответ: `choices[0].message.content`.

Трафик OpenCode Go мониторят на абьюз, поэтому в запрос добавляются
`User-Agent: aistick/0.1` и заголовок `x-opencode-session` (UUID, генерируется
на старте устройства) — как просит их документация.

### TLS

`WiFiClientSecure::setInsecure()` — без пиннинга сертификата. Просто и
работает, но MITM-незащищено. Для v1 принято осознанно; в коде помечено
комментарием.

Таймауты: connect 5 с, чтение 15 с. Устройство не может зависнуть навсегда.

## 8. Экран и шрифт

Поворот ландшафт (константа в `settings.h`, точное значение 1 или 3
уточняется на живой плате).

```
┌─────────────────────────────┐
│ WiFi ▂▄ 78%      deepseek   │  статус-бар, 14 px
├─────────────────────────────┤
│                             │
│   ● RECORDING...            │  тело, ~112 px, 7 строк
│                             │
├─────────────────────────────┤
│                       2/3   │  индикатор страниц, 9 px
└─────────────────────────────┘
```

Цвета по ТЗ: IDLE — зелёный/синий, RECORDING — красный `● RECORDING...`,
ожидание ответа — жёлтый `Thinking...`.

Шрифт: моноширинный **JetBrains Mono Regular** (лицензия OFL, встраивание
разрешено) в формате `GFXfont`, 16 px, 4-битное сглаживание, диапазон ASCII +
кириллица (U+0400–U+045F). Генерируется скриптом `tools/make_font.py`
(fonttools + Pillow), результат коммитится. Если генерация упрётся в грабли —
запасной вариант встроенный `efontUnicode` из M5GFX, он кириллицу тоже умеет.

Перенос строк по словам и по пиксельной ширине; длинное слово рвётся
принудительно. Всё идёт по кодпоинтам UTF-8, поэтому разрез посреди
кириллической буквы технически невозможен — это проверяется тестом.

## 9. Ошибки

| Ситуация | Что на экране |
|---|---|
| Wi-Fi не подключился | `WiFi: <причина>` + повтор по BtnA |
| HTTP не 200 | `STT error 401` + первые ~60 символов тела |
| Whisper вернул пусто | `Не расслышал` → IDLE |
| Запись < 300 мс | `Слишком коротко` → IDLE |
| Любая ошибка | через 5 с или по BtnB → IDLE |

Секреты только в `include/config.h`, он в `.gitignore`. В репозитории лежит
`config.h.example`.

## 10. Наблюдаемость

Прошивка без экрана-консоли, поэтому:

- Serial 115200 с тегами `[audio]`, `[stt]`, `[llm]`, `[ui]`.
- **Журнал в RTC-памяти.** Последние ошибки и этапы работы сохраняются в
  RTC-память, которая переживает перезагрузку и не обнуляется при сбросе.
  После перезагрузки причина видна на экране и по Serial. Это позволяет
  отлаживать падения, которые иначе выглядят как «устройство просто
  перезагрузилось».

## 11. Порядок работы

### Милестоун 0 — проверка рисков (делаем первым)

Прошивка примерно на 50 строк: включает PSRAM, пишет 3 секунды с микрофона,
стримит запись в base64 по Serial. Скрипт на Mac собирает из этого `test.wav`,
пользователь слушает.

Проверяет три самых рискованных допущения сразу: включается ли PSRAM на этой
плате, заводится ли PDM-микрофон, корректны ли параметры захвата. Если звук
чистый и PSRAM виден — дальше всё предсказуемо. Если нет — это выясняется на
50 строках, а не на 600.

### Дальше

2. Каркас проекта: `platformio.ini` (оба окружения), `settings.h`,
   `config.h.example`, `.gitignore`, README. Проверка, что тесты запускаются
   через `tools/run_tests.sh`.
3. Модули WAV и text_wrap + нативные тесты. Полный захват 8 секунд в PSRAM с
   корректным заголовком.
4. STT: Wi-Fi, TLS, потоковый multipart, ответ Groq. Первая живая проверка
   сквозного пути аудио → текст.
5. LLM: OpenCode Go, парсинг JSON.
6. UI: генерация шрифта, перенос, пагинация, статусы.
7. Сквозной прогон на устройстве, отладка по журналу в RTC-памяти.
