# Как поучаствовать

Проект маленький и живой, поэтому правил мало. Главное — не сломать то, что
уже проверено на железе, и не принести секретов в историю.

## Самое важное: секреты

В репозиторий **не попадает** `include/config.h`. Там живут Wi-Fi, ключ
модели, адрес прокси и его токен, доступы к Tuya. В репозитории лежит только
шаблон `include/config.h.example`.

Перед каждым коммитом стоит взглянуть на `git diff --cached` глазами: если
там мелькнул ключ, адрес сервера или токен — коммитить нельзя.

Ещё: в описаниях коммитов, в issue и в скриншотах тоже не должно быть ни
адресов, ни ключей. Скриншоты экрана стика безопасны, а вот вывод `config.h`
— нет.

## Тесты

Вся логика живёт в `src/pure/` — это модули без Arduino и без сети. Они
собираются обычным `clang++` и проверяются без железа:

```bash
tools/run_tests.sh
```

Прогон проверяет модули ещё и вторым компилятором (`g++`). Это не
формальность: однажды забытый `#include <cstring>` проходил на Mac и валил
CI, потому что там другой набор заголовков. Если добавил новый модуль —
добавь и тест `test/test_имя.cpp` с `puretest::summary("имя")`.

**Правило простое:** новая логика — сначала чистый модуль с тестами, и только
потом склейка с железом в `src/*.cpp`. Так почти вся логика проекта
проверяется без стика.

## Что куда класть

| Куда | Что |
|---|---|
| `src/pure/` | логика без Arduino: разборы, расчёты, состояния |
| `src/*.cpp` | склейка: сеть, экран, кнопки, железо |
| `include/settings.h` | настройки, которые не секретны |
| `include/config.h.example` | шаблон секретов (сам `config.h` — в `.gitignore`) |
| `data/plugins/` | плагины, которые заливаются в файловую систему стика |
| `deploy/` | то, что разворачивается на сервере |
| `tools/` | вспомогательные скрипты: тесты, шрифт, лог, эмулятор экрана |
| `test/` | нативные тесты чистых модулей |

## Стиль

- **Комментарии и сообщения коммитов — по-русски.** Так проект писался с
  начала, так и продолжаем.
- Комментарий объясняет **почему**, а не что. Строка `x += 1` без «зачем» не
  нужна никому.
- Если что-то сделано неочевидно (костыль, обход, компромисс) — рядом должно
  быть написано, почему именно так и что будет, если сделать иначе.
- Имена файлов, функций и переменных — по-английски, как принято в C++.
- Формат кода: два пробела, ширина строки — 80 колонок.

## Плагины

Плагин — это файл `.ais`: шапка из комментариев и тело на крошечном языке.
Подробности и список доступных функций — в разделе «Плагины» основного
README. Если делаешь плагин для общего пользования, ему место в отдельном
репозитории [aistick-plugins](https://github.com/elcrazycol/aistick-plugins),
а не здесь.

Помни: у скрипта нет ни файлов, ни произвольных пинов, ни секретов — только
белый список функций. Расширять этот список стоит с осторожностью: плагины
скачиваются из интернета и запускаются на устройстве.

## Железо

Проверять изменения лучше на настоящем стике: эмулятор экрана
(`tools/mock_screen.py`) повторяет отрисовку пиксель в пиксель, но кнопки,
микрофон и сеть он не заменит.

Полезное:

```bash
pio run -e esp32dev -t upload      # прошивка
pio run -e esp32dev -t uploadfs    # файловая система с плагинами
python3 tools/capture.py --monitor # лог устройства
python3 tools/mock_screen.py       # картинки экранов в docs/images
```

## Коммиты и пул-реквесты

- Один коммит — одно изменение. Сообщение в повелительном наклонении:
  `feat: поиск в интернете`, `fix: кнопка не работала после плагина`.
- Префиксы: `feat`, `fix`, `perf`, `docs`, `test`.
- В пул-реквесте опиши, **что проверил**: тесты, железо, что именно нажимал.
  Если что-то не проверял — так и напиши, это нормально.

CI на каждый push прогоняет тесты. Красный CI — сначала почини, потом проси
ревью.

**English.** Short version: never commit `include/config.h` (it holds Wi-Fi,
API keys and the proxy token — the repo only has `config.h.example`); put new
logic in `src/pure/` with a test in `test/` so it can be checked without
hardware; run `tools/run_tests.sh` before pushing; comments and commit messages
are in Russian in this project. PRs in English are welcome.
